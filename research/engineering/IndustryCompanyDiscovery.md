# Engineering Concept: Industry Company Discovery ("Find More Companies")

## What it is

`backend/industry/industry.discovery.js` finds companies **not yet** in Athena's database that share a target's sector/industry classification, via a live query against Yahoo Finance's unofficial equity screener (`YahooFinanceProvider.searchCompaniesByClassification()`). It's the direct counterpart to `industry.peerDiscovery.js`, which only ranks companies **already** in Athena's database - this module exists specifically to grow a reference universe that's too small to benchmark against (see `research/finance/IndustryAnalysis.md`'s documented reference-universe limitation).

## Why we use it

`ReferenceUniverse.md` documents that Athena's benchmark universe is bounded by what a user has previously searched or imported - a real, honest limitation, but one with an obvious lever: if a user knows a company belongs in the same industry, they should be able to add it without leaving the Industry page or knowing the exact ticker in advance. A live classification search closes that gap without pretending Athena has a complete industry census - the results are explicitly framed as unreviewed suggestions (`formatDiscoveryResponse()`'s `limitation` field), exactly like `industry.peerDiscovery.js`'s "Potential Peers."

## Alternatives considered

- **A hardcoded list of well-known companies per industry.** Rejected outright - the Sprint 13 brief is explicit ("Do not hard-code classifications for a handful of companies as a production solution"), and a static list would silently go stale and could never cover industries the team didn't anticipate.
- **Reusing Yahoo's existing name/ticker search (`searchTickerByName`) with the industry name as the query string.** Tested and rejected - that endpoint is a fuzzy text matcher over company names/tickers, not a classification filter; querying it with "Consumer Electronics" returns whatever companies happen to have matching text in their name, not companies actually classified in that industry.
- **Yahoo's unofficial equity screener endpoint** (`POST /v1/finance/screener` with an `{operator: "eq", operands: ["industry", ...]}` query). Verified live before building against it: querying "Consumer Electronics" correctly surfaces Samsung, LG, Sony, and Panasonic alongside Apple - genuine classification-based results, not a text match. Unofficial and undocumented, but the same trust model Athena already accepts for `getCompanyProfile` and `searchTickerByName` (both already reverse-engineered against Yahoo's cookie+crumb auth in `yahooAuth.js`) - not a new category of risk, just a new endpoint under the same one.

## Trade-offs

**For the live screener query:** genuinely useful, industry-accurate results with zero new infrastructure or maintenance burden (no list to keep updated). Confirmed to work for both `industry`-level and `sector`-level classification queries, mirroring `industry.peerDiscovery.js`'s own fallback levels.

**Against it:** the screener is unofficial and could change or be rate-limited without notice - the same risk profile Athena already accepts elsewhere, made explicit here rather than hidden. It's also provider-specific: `TwelveDataFinancialDataProvider` has no equivalent capability, so `financialDataProvider.js`'s base class throws a clear 501 "not supported" error rather than silently returning an empty list that would look identical to "no companies found" (see `financialDataProvider.test.js`).

## The cross-listing noise problem, and how it's solved

The screener returns one row per *listing*, not per *company* - a live test query for "Consumer Electronics" returned Apple **13 times** across 13 different exchanges (Colombia, Argentina, Mexico, Brazil, Poland, Germany, Switzerland, ...), most with near-zero trading volume and market caps skewed by currency (one Colombian-peso-denominated listing reported a "market cap" over 10^15 due to currency scale alone, dwarfing Apple's real ~$4.4T figure). Sorting by `averageDailyVolume3Month` within each normalized-company-name group reliably separates the one genuine, liquid listing from the phantom cross-listings (verified against the same live data: `AAPL`'s real Nasdaq listing had 56M in 3-month average volume; the noise listings ranged from 0 to a few hundred) - see `yahooFinance.mapper.mapYahooScreenerCandidates()` and its test suite for the exact grouping/dedup logic.

## How Athena implements it

`GET /api/industry/:ticker/discover` resolves the target's classification, calls the provider abstraction, excludes both the target itself and any candidate already tracked in Athena's `Company` collection, and caps the result at `DISCOVERY_LIMIT` (20). Nothing is imported at this point - it's a read-only suggestion list, same as `industry.peerDiscovery.js`. `POST /api/industry/:ticker/discover/import` takes the user's explicit selection and, per-ticker, imports the company profile (`companyService.importCompany`) and then financial statements (`financialsService.importFinancialStatements`) - reusing both existing import flows rather than duplicating them - reporting each ticker's outcome independently (imported / partial - company only / failed) so one bad ticker never blocks the rest of the batch, the same "exclude and explain" discipline as `comps.service.js`'s `unavailablePeers`. On success, `industry.service.invalidateUniverseCache()` clears the cached benchmark bundle so the newly-imported companies are reflected on the next request rather than waiting out the 5-minute TTL (see `BenchmarkCaching.md`).

## Interview questions

1. *"Why does Athena trust an undocumented Yahoo endpoint for this feature?"* — Because Athena already does, for `getCompanyProfile` and `searchTickerByName` - both call reverse-engineered Yahoo endpoints authenticated via a scraped cookie+crumb pair. Using a third undocumented endpoint under the same authentication and error-handling pattern is a consistent extension of an already-accepted trust model, not a new category of risk - and it was verified live against real data before being built against, not assumed to work from documentation that doesn't exist.
2. *"Walk through why the same company can appear a dozen times in one screener query, and how Athena handles it."* — Yahoo's screener matches at the *listing* level, and a large multinational company is cross-listed on many exchanges (ADRs, dual listings, depositary receipts) - each with its own quote, often with near-zero real trading activity. `mapYahooScreenerCandidates()` groups by a normalized company name and keeps only the highest-3-month-average-volume listing per group, which reliably identifies the one listing that's actually liquid and real rather than a phantom cross-listing.
3. *"Why sort by trading volume to pick the 'real' listing instead of market cap, which Yahoo already sorts by?"* — Market cap across different listings of the same company is denominated in different currencies with no FX normalization applied, so a Colombian-peso listing can show a "market cap" many orders of magnitude larger than the real, correctly-denominated figure purely from currency scale - verified with live data. Trading volume isn't subject to that distortion in the same way, and a near-zero-volume listing is a strong, currency-independent signal that it's not the primary market for that stock.
4. *"Why does importing a discovered company also import its financial statements, not just its profile?"* — Because `industry.peerDiscovery.resolveReferenceUniverse()` requires imported financial statements for universe membership (a company profile alone contributes nothing to a margin/growth/ROE benchmark) - importing only the profile would leave the newly-added company invisible in the benchmark until a second, separate action, which defeats the purpose of "Find More Companies" as a way to close a specific gap the user is looking at right now.
