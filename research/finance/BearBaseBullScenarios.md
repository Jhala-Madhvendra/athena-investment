# Bear / Base / Bull Scenarios

## 1. Definition

Bear/Base/Bull is a three-scenario framing convention — pessimistic, neutral, and optimistic — used to bound a range of outcomes with a small, digestible set of named narratives rather than either a single point estimate or an overwhelming matrix of possibilities. Athena already uses this framing for DCF valuation (`research/finance/ScenarioAnalysis.md`, Sprint 6/7 — varying revenue growth/EBIT margin); Sprint 16 introduces the same three-scenario convention for portfolio-level shocks, as one of six presets alongside Market Correction, Technology Selloff, and Broad Market Stress.

## 2. The formula

No new formula — each of Bear/Base/Bull is an ordinary multi-factor scenario (`AdvancedScenarioAnalysis.md`), just with a specific, named, editable rule set:

```
Bear:  Market -15%,  Technology -25%,  Financial Services -10%
Base:  Portfolio-wide 0% (a zero-movement baseline)
Bull:  Market +10%,  Technology +15%,  Financial Services +10%
```

## 3. Intuition

Base establishes the reference point ("here's the portfolio's current modeled value, unchanged"); Bear and Bull bound a plausible pessimistic-to-optimistic range around it, giving a reader an immediate sense of how much the portfolio's value could swing under stated adverse or favorable conditions — a single number invites false precision, while three named scenarios communicate a range without requiring the reader to build a matrix themselves.

## 4. Why investors care

It's a familiar, low-friction way to reason about a range of outcomes without needing to specify an entire probability distribution. Comparing Bear against Bull (`Scenario Comparison`, see `research/engineering/ScenarioComparisonEngine.md`) surfaces how *sensitive* a given portfolio is to directional market movement — a portfolio where Bear and Bull produce nearly identical outcomes is structurally different (less directionally exposed) from one where they diverge sharply, independent of which one a reader thinks is more likely.

## 5. Assumptions

The specific shock values (-15%/-25%/-10% for Bear, mirrored for Bull) are a **documented, adjustable starting convention**, not derived from any company-specific or portfolio-specific statistical measure — the same honesty already established for DCF's ±2pp scenario deltas (`ScenarioAnalysis.md` Section 5). They are not claimed to be the "correct" bear/bull spread for every portfolio; a highly cyclical, sector-concentrated portfolio might warrant a wider spread, a defensive one a narrower one. The user can load a preset and then edit every rule before running it (`AdvancedScenarioProductDesign.md`).

## 6. Limitations

Bear/Base/Bull carries **no probability** — Athena never states or implies "Bear Case: 20% likely." Presenting three named scenarios can itself imply an unwarranted sense of completeness (as if reality is limited to exactly these three paths); Athena's UI and copy always label them "Hypothetical preset" to counter that impression. The sector shocks (Technology, Financial Services) only affect holdings whose `Company.sector` field exactly matches those Yahoo-sourced labels — a portfolio using a different sector taxonomy (or with unclassified holdings) will see those specific rules simply not apply to the mismatched holdings, a disclosed limitation rather than a silent gap.

## 7. How Athena implements it

`backend/portfolio/portfolio.scenario.presets.js` defines `bear`/`base`/`bull` (plus `marketCorrection`/`technologySelloff`/`broadMarketStress`) as static, documented rule-set constants — never computed, never persisted, never regenerated by AI. `GET /api/portfolio/scenarios/presets` returns deep copies of every preset (mutating a loaded preset in the frontend builder can never corrupt the canonical source) with `isHypothetical: true` and `label: "Hypothetical preset"` on every entry. The frontend's `ScenarioBuilder.jsx` loads a clicked preset's rules into the editable rule list — the user can then add, remove, or edit any rule before running, exactly like a fully custom scenario.

## 8. Common mistakes

- **Assuming Base always means "the most likely outcome"** — it means "zero additional hypothetical shock," a reference point for comparison, not a probability-weighted expectation.
- **Assigning a probability to Bear or Bull** ("there's a 20% chance of the Bear Case") — Sprint 16 explicitly excludes probability modeling (`research/product/AdvancedScenarioProductDesign.md` Section 8); doing so would require a defensible statistical model Athena doesn't have.
- **Treating the preset's exact shock values as universally correct** rather than an editable starting point — the whole point of loading a preset into an editable builder, rather than running it as a locked black box, is that the user is expected to adjust it to their own view.

## 9. Scenario vs. forecast

Bear/Base/Bull is three scenarios, not three forecasts, and specifically not a 3-point discrete probability distribution over the future. "If the Bear Case assumptions occur, the modeled portfolio impact is -22%" is the only claim Athena makes — never "there's a meaningful chance this happens" or "this is more likely than the Bull Case."

## 10. How analysts use it

Bear/Base/Bull is a widely recognized shorthand across equity research and portfolio risk communication precisely because it compresses a continuous range of outcomes into three memorable, comparable reference points without requiring a full probabilistic model — useful specifically when the goal is quick, communicable range-bounding rather than statistically rigorous forecasting.

## 11. Interview questions

1. **"Does Athena's Bear Case represent the worst plausible outcome for a portfolio?"** — No — it represents one specific, editable hypothetical (Market -15%, Technology -25%, Financial Services -10%), not the worst case in any calibrated sense. A user can construct a more severe custom scenario, and Athena makes no claim that the Bear preset bounds the downside.
2. **"Why is Base modeled as a zero-shock scenario instead of the portfolio's expected/most-likely trajectory?"** — Because "expected trajectory" would require Athena to make a forecast — exactly what this feature is designed not to do. Zero shock is an unambiguous, defensible reference point: "here's the current value, unchanged," against which Bear and Bull's modeled deviations are easy to interpret.
3. **"If a user disagrees with the -15% Bear Case market shock, what should they do?"** — Edit it. Every preset loads into the same editable rule builder a fully custom scenario uses — the preset values are a documented starting convention, not a locked, authoritative assumption, and the product is explicitly designed to expect the user to adjust them.
